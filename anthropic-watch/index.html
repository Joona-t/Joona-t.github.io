      Model release · 7 Oct 2026

      Claude Haiku 5.5: the small, fast model

      In one line. Haiku 5.5 is Anthropic's cheapest and fastest model: $0.10 / $0.50 per million tokens on short prompts, a 1M-token window, adaptive thinking with an effort dial, and a big jump over Haiku 4.5 on computer-use and knowledge-work tests.
      Model ID
      claude-haiku-5-5
      Released
      7 Oct 2026
      Price / MTok
      $0.10 in · $0.50 out (≤100K prompt)
      Context
      1M tokens
      Max output
      128K (300K batch beta)
      Default effort
      medium
      Knowledge cutoff
      Jun 2026
      Input → output
      Text + images → text

      What's new vs Haiku 4.5

      • Adaptive thinking + effort. The first Haiku with an effort dial (low → max). Thinking is on by default; the model decides how much to reason.
      • 5× the window, 2× the output. Context grew from 200K to 1M tokens. Max output grew from 64K to 128K. Thinking tokens count toward max_tokens.
      • Tiered, much lower prices. 90% cheaper per token for prompts up to 100K, 50% cheaper above. Anthropic estimates about 75% savings on average.
      • New tokenizer. The same text counts as about 30% more tokens than on Haiku 4.5, the same tokenizer Claude 4.7 and later use.
      • Browser use on the Claude API and Google Cloud. Computer use moves to computer_toolset_20260801.
      • Safety. Anthropic reports better results on almost all its alignment evaluations. It is the first Haiku with built-in safeguards for a narrow range of high-risk cyber requests.

      What it says: a huge generational jump (OSWorld 15.7% → 72.4%), close to Sonnet 5.5 on office and computer work, and well behind it on hard terminal coding (39.2% vs 70.6%). That gap is the classic small-model trade-off.

      Worked example: the real saving

      A 1,000-token prompt on Haiku 4.5 is about 1,300 tokens on Haiku 5.5.

      Haiku 4.5:  1,000 × $1.00 / 1M = $0.00100
Haiku 5.5:  1,300 × $0.10 / 1M = $0.00013   → ≈ 87% cheaper

      The headline is 90% cheaper per token, but on a short prompt the real saving is about 87% because the same text uses more tokens. Anthropic's ~75% average is lower again because it includes long prompts, which only drop 50%.

      Breaking changes if you're migrating

      • Manual extended thinking (budget_tokens) errors. Use adaptive thinking and effort.
      • Non-default temperature, top_p, top_k return 400.
      • Assistant prefill errors. End messages on a user turn.
      • Responses can start with a thinking block. Select blocks by type, not position.
      • Thinking text is hidden by default. Set thinking.display: "summarized" to see a summary.
      • Editing earlier turns invalidates thinking blocks. Keep conversations append-only.

      Self-check

      Prices fell 90% per token. Why is the short-prompt saving nearer 87%?

      The new tokenizer counts the same text as ~30% more tokens: 1.3 × $0.10 = $0.13 against $1.00 before.

      Your code reads content[0].text. What breaks?

      The first block can be a thinking block. Find the block whose type is "text".

      A 150K-token document needs summarising. How do you cut cost?

      Split it into chunks under 100K tokens to get the $0.10 / $0.50 rate, and use the Batch API for another 50% off if you can wait.

      Learn

      How a Claude model works

      Goal. Understand what happens between your prompt and the reply, why small models are fast and cheap, and which levers you control.

      From prompt to reply

      1. Tokenize. Text is split into tokens, which are word pieces. Prices and limits are counted in tokens.
      2. Embed. Each token becomes a long list of numbers.
      3. Transformer layers. Attention lets every token weigh the others. Many layers stack.
      4. Think (optional). With adaptive thinking, the model can write reasoning tokens before answering.
      5. Predict the next token. Pick one, append it, repeat until done.
      Think first: why does higher effort make an answer both better and more expensive?
      Answer

      Higher effort means more thinking tokens, and those are billed as output. More reasoning helps on hard problems, but you pay for every token.

      Why there are tiers

      Bigger models do more calculation per token. That buys capability but costs time and money. Anthropic ships tiers so you can choose: Haiku (fastest, cheapest), Sonnet (the balance), Opus (deepest), and in 2026 the Fable and Mythos lines above that.

      How small models get good

      The standard industry recipe is distillation. A large teacher model answers many prompts, and a smaller student is trained to reproduce those answers. The student keeps much of the teacher's skill on common tasks but loses some breadth: rare facts and the hardest multi-step reasoning.

      Not published Anthropic hasn't published how Haiku is trained. Distillation is the usual method, but it's an inference, not a confirmed fact about Claude.

      Reading benchmarks without being fooled

      • Versions change. Terminal-Bench 2 and Terminal-Bench 4 are different tests. Don't draw a trend line across them.
      • Effort changes scores. Launch tables usually show each model at its best setting.
      • Vendor vs independent. Third-party runs of the same test often come out lower.
      • Your task is the real benchmark. Write 20 real examples and run the cheapest model first.

      Glossary

      Token
      A chunk of text, often a word piece. Models read, write and bill by tokens.
      Tokenizer
      The rule set that splits text into tokens. Claude 4.7 and later use a newer tokenizer that produces ~30% more tokens for the same text.
      Context window
      The most tokens a model can see at once: prompt, history and reply.
      Max output
      The most tokens a model can write in one response, thinking included.
      Extended thinking
      The earlier manual mode where you set a thinking budget (budget_tokens).
      Adaptive thinking
      The newer mode where the model decides when and how much to think.
      Effort
      A dial (low, medium, high, xhigh, max) that steers how much work the model puts in.
      Distillation
      Training a small model to imitate a large model's outputs.
      Prompt caching
      Reusing work for a repeated prompt prefix, billed at a fraction of the input price.
      Batch API
      Asynchronous, half-price processing for jobs that can wait.
      SOTA
      State of the art: the best result available at a given time.
      SWE-bench
      Real GitHub issues the model must fix. "Verified" is a human-checked subset; "Pro" is a harder successor.
      OSWorld
      Tasks completed by operating a real computer.
      GPQA Diamond
      Graduate-level science questions written to resist web search.
      Humanity's Last Exam
      Very hard expert questions across many fields.
      Elo
      A relative rating from head-to-head comparisons. Higher wins more often.
      Deprecation / retirement
      Deprecated models still work but have an end date. Retired models no longer serve requests.
